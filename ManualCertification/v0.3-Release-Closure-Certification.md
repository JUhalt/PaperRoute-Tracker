# PaperRoute v0.3 Closure Certification

This checklist certifies the release-blocking closure work added after the
279/279 Route / Version History checkpoint.

## A. Automated gate

Run:

```powershell
git diff --check
dotnet test .\PaperRoute.Tests\PaperRoute.Tests.vbproj -c Release
```

Expected: **297/297**.

## B. Version deletion transaction

Use a disposable `ZZZ-CERT-v0.3-*` manuscript.

### B1. Metadata-only deletion

1. Add a metadata-only version.
2. Make it current.
3. Delete it from Version History.
4. Confirm the warning explains current-version fallback.
5. Choose **Cancel** on Manuscript Details.
6. Reopen the manuscript.

Expected: the version still exists because the working-copy deletion was
discarded.

### B2. Managed snapshot deletion

1. Add a new version using **Copy into PaperRoute Library** and a disposable
   local file.
2. Save & Close Manuscript Details.
3. Reopen and select the version.
4. Copy/note the managed snapshot path shown in Version History details.
5. Delete the version.
6. Save & Close.
7. Reopen Manuscript Details.

Expected:
- the version record is gone;
- Current Version falls back to the newest remaining version, or becomes empty
  if no versions remain;
- the managed version directory is gone.

Optional PowerShell verification:

```powershell
Test-Path "<managed-version-directory>"
```

Expected: `False`.

### B3. Linked-file deletion

1. Add a version using **Link to the original file**.
2. Save & Close.
3. Reopen and delete that version.
4. Save & Close.

Expected:
- the PaperRoute version record is gone;
- the original external file still exists.

## C. Main-board responsive layout

At each display scaling setting, restart PaperRoute and use the smallest
supported main-window size.

Test:
- 100%
- 125%
- 150%

Expected at each scaling:
- Help / Settings / Data / Add Manuscript remain reachable;
- Needs Attention controls remain reachable;
- Search / Stage / Sort / Clear wrap rather than disappear;
- manuscript title and journal text do not collide with action buttons;
- Open / Move to File Drawer (or Restore) / Delete remain reachable;
- action buttons wrap onto an additional row when necessary;
- View route remains reachable;
- no excessive permanent horizontal scrolling at the supported minimum size;
- keyboard Tab navigation can reach all main actions.

# PaperRoute Tracker v0.4.0 — Submission Readiness

**Released September 13, 2026.** PaperRoute v0.4.0 is the current Stable release. Release certification covered native Windows scaling and keyboard behavior, clean installation, installed v0.3-to-v0.4 migration, the real Preview updater path through v0.4.0-rc.1, and release-candidate installer/update/portable asset verification.

PaperRoute v0.4 connects journal preparation to the exact manuscript version, packet files, and journal submission they belong to. Preparing a packet or completing a checklist does not claim that a submission occurred.

## What's new

- **Reusable journal checklists** — maintain requirements in the Journal Library and apply them to manuscript-specific readiness profiles. Track unresolved, complete, and not-applicable items while preserving each profile's copied requirements and progress.
- **Submission Packet Vault** — assemble blinded manuscripts, cover letters, figures, supplements, and other file records around one exact Version History entry. Link a packet to a readiness profile, actual submission, and revision round when applicable.
- **Three file choices** — keep external links, retain PaperRoute-managed snapshots, or record metadata without a local file.
- **Local file-integrity checks** — explicitly record SHA-256 fingerprints and use Check Files to identify unchanged, changed, missing, unavailable, or unchecked files. Checks read files without rewriting their contents; replacing a saved fingerprint requires confirmation.
- **Connected workflow navigation** — move between Manuscript Details, readiness, Version History, packets, and actual submissions while retaining unsaved work. Record Submission is an explicit action; revisions can remain associated with the existing journal submission.
- **Responsive workflow dialogs** — long notes and expanded windows keep packet and readiness controls reachable. Submission Details reserves space for the portal summary and editorial history, and action/link text has improved theme contrast.
- **Recovery and restore hardening** — invalid associations are rejected before file operations, managed deletion remains tied to successful saves, and recoverable staged content is retained when recovery encounters a conflict.

## Save boundaries and file meaning

Choose **Save & Close** in the child dialog, then **Save & Close** in **Manuscript Details** to persist the complete workflow. Canceling Manuscript Details discards its unsaved manuscript changes. Preparing files and resolving readiness are advisory; they do not record a submission or silently change manuscript history.

Integrity results describe the **last observation**, not continuous monitoring. Reopened files with saved fingerprints start as **Not checked** until checked again. A fingerprint can detect a changed external file but cannot reconstruct its previous contents. Use a managed copy when PaperRoute should retain the actual bytes.

## Compatibility and backup

- Storage **schema 5** adds readiness and packet data while preserving existing manuscript, version, and submission histories. Existing libraries need no synthetic preparation records.
- Portable ZIP backup/restore preserves readiness profiles, journal checklist templates, exact packet associations, saved fingerprints, and managed snapshot contents.
- Externally linked files remain references to their original paths. Deleting a linked record does not delete its external original.
- Excel exports cover the supported manuscript, submission, decision, and correspondence fields; use a ZIP backup to preserve the full library.
- Keep a pre-upgrade v0.3 backup before moving a real library to v0.4. See the [upgrade notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/master/UPGRADE_NOTES.md) and [user guide](https://github.com/JUhalt/PaperRoute-Tracker/blob/master/docs/USER_GUIDE.md).

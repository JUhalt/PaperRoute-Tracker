# PaperRoute Tracker v0.9.2 — 1.0 Hardening

This release readies PaperRoute for 1.0 without adding a new workflow. Your files and your library are harder to lose and easier to recover, the window no longer stalls on a large library, and PaperRoute can be worked from the keyboard and with a screen reader throughout. Your library stays on Schema 9.

## Included

- **Files are moved, not deleted.** When you delete a manuscript, a version or a packet file and save, PaperRoute moves its copies into a dated `removed` folder in `Documents\PaperRoute Library`, which nothing empties. A save now touches only files your library knew about, so a library recovered from its older copy can no longer remove another manuscript's newer files.
- **Recovery.** If Windows shuts down with unsaved edits on a manuscript page, or an error ends the session, the next start offers to open the manuscript with them. An unexpected error shows a plain window that keeps your unsaved page reachable, and writes a report to a `logs` folder on your computer; nothing is sent. When PaperRoute cannot start, a window says what failed, and if the library is damaged and a good copy is beside it, offers to put it right.
- **Backup and restore.** Backups record which PaperRoute made them, and Restore refuses one written in a newer format than it can read, before anything changes. Restore shows your current library beside the backup, then restarts PaperRoute into the restored library. Backup, Restore and installing any later update ask about unsaved edits first, and a failed save stays in view until a save succeeds.
- **Safer questions.** Deleting a manuscript from its page asks you to type DELETE, Delete Journal Submission says what goes with it, and No is the default on every delete question.
- **Speed.** On a 500-manuscript test library, the Board and the page switches that took seconds now take tens of milliseconds, startup takes about 1 s instead of 4.4 s, opening a manuscript under 0.1 s instead of 2.9 s when the computer is not busy, and Backup no longer freezes the window for 31 s.
- **Keyboard and screen readers.** Every window can be worked from the keyboard, Esc cancels every dialog, every input has a name Narrator reads, and status lines are read out without moving focus. The status line now says what you just did, such as a manuscript moved to the File Drawer, and the Board's search box, Save and a few other controls show their shortcut when you point at them.
- **Contrast themes.** Under a Windows contrast theme, every color PaperRoute draws comes from the theme, and route maps use patterns as well as color.
- **Display.** Sixteen windows now follow the display's scale on one rule, and the main window fits a 1366x768 laptop. PaperRoute 1.0 is checked at 1920x1080 up to 150% and at 1366x768 up to 125%.
- **Motion and the Windows 11 frame.** Pages cross-fade and buttons ease into their hover color, unless Windows' Animation effects setting is off; a key or a click never waits for it. Every window has rounded corners and a title bar that matches the theme.
- **Privacy and security.** A [privacy policy](https://github.com/JUhalt/PaperRoute-Tracker/blob/v0.9.2/PRIVACY.md) now says what PaperRoute can contact and what it never sends. PaperRoute checks for updates when it starts, sending nothing about you or your library, and Preferences can turn that off. Links from a library open only if they are web links, and opening a recorded program or script asks first.
- **Not code-signed yet.** Setup is still not code-signed, so Windows warns before it runs; the User Guide's Installing section explains the warning and how to check the download against `SHA256SUMS.txt`. The application to the SignPath Foundation for free code signing follows this release, and the [code signing policy](https://github.com/JUhalt/PaperRoute-Tracker/blob/v0.9.2/CODE_SIGNING.md) says what will be signed.
- **Also:** leaving the File Drawer keeps why a manuscript was filed; Record Submission... starts at the target journal and keeps its Journal Library link; empty Board shelves say what belongs on them; a new version is named after its file; the author, affiliation or journal you just added stays selected; an import whose save fails is taken back out, ORCID's included; an export to a file open in another program, such as a workbook open in Excel, says to close it there and try again; packet dates read as Version History's do; counts read in plain words, "1 day" rather than "1 days"; calendar dates no longer move with the time zone; Dark no longer leaves light check marks, buttons or date fields; dialog buttons and field labels line up; releases no longer include a Portable.zip and ship the third-party licenses; and the User Guide gains Installing, Uninstalling, Recovering your library and Accessibility sections.

## Before upgrading

**Save any open manuscript page before you choose Download & Restart:** the version you are updating from does not ask about unsaved edits, so they would be lost. From v0.9.2 on, updating asks first. v0.9.2 uses the same **Schema 9** library as v0.9.0 and v0.9.1 and migrates no data; v0.9.1 can still open a library v0.9.2 has used. Restore a backup made by v0.9.2 with v0.9.2 or later. If PaperRoute runs on more than one computer that shares a Documents folder, update every one of them before saving on any of them. Only the 0.9 releases are supported for updating straight to 1.0. The [upgrade notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/v0.9.2/UPGRADE_NOTES.md) have the details.

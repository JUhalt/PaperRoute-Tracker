# PaperRoute Tracker v0.5.0 — Reviewer Response Workflow

PaperRoute v0.5 turns reviewer and editor feedback into a structured revision workflow within the journal submission that received it. Track each request, draft a response, and export an editable response-to-reviewers document without an AI service or online account.

## What's new

- **Reviewer Response Matrix** — open **Reviewer Responses...** in Submission Details to add, edit, remove, filter, and reorder comments and actions.
- **Explicit decision and round links** — every item belongs to an existing editorial decision in that submission and an explicitly entered positive revision-round number. Multiple reviewers and rounds retain their own labels and associations.
- **Response drafting** — record reviewer/editor labels, comments, actions, manuscript locations, working notes, and draft responses. Track **Unresolved**, **In progress**, **Addressed**, and **Not applicable** states.
- **Editable Markdown export** — review and edit a complete response draft before saving it to a file. The export includes item status, working notes, and decision/round context in stored order.
- **Schema 6 persistence** — reviewer responses are preserved through manuscript editing, saving, recovery, and portable backup/restore. Referenced editorial decisions cannot be deleted until their response items are reassigned or removed.

## Saving and exporting

Choose **Save Comment** in the item editor, **Save & Close** in the matrix, **Close** in Submission Details, and **Save & Close** in Manuscript Details to persist the complete workflow. Canceling Manuscript Details discards all its unsaved changes, including accepted matrix edits.

Exporting creates a separate draft; it does not save the matrix, mark items addressed, or record a submission. The export contains the complete matrix regardless of its status filter and includes working notes. Review the preview before sharing it. Preview edits do not change matrix data, and subsequent matrix changes do not update an existing exported file.

Response statuses describe revision work without changing manuscript lifecycle state. A normal revision remains part of the existing journal submission.

## Compatibility and backup

- Storage **Schema 6** preserves existing manuscript, version, submission, readiness, and packet histories while adding reviewer responses. Migration from Schema 5 validates the library and retains the original data and previous schema marker without inventing feedback or rounds.
- Create and retain a separate v0.4 portable ZIP backup before upgrading.
- Restore backups made by v0.5 with **v0.5 or later**. Older restore code may ignore reviewer-response fields, even though older applications refuse to open a Schema 6 library directly. Return to v0.4 only with the pre-upgrade v0.4 backup.
- The Excel workbook remains a partial interchange format. Use ZIP backup/restore for the complete workflow, and retain externally linked original files separately.

See the [user guide](https://github.com/JUhalt/PaperRoute-Tracker/blob/master/docs/USER_GUIDE.md) for the workflow and [upgrade notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/master/UPGRADE_NOTES.md) for compatibility details.

# PaperRoute Tracker v0.9.1 — Packet File Safety

This patch fixes one thing in v0.9.0: saving could delete the packet snapshots of manuscripts the open library did not contain. Nothing else changes.

## Fixed

- **Saving leaves other manuscripts' files alone.** PaperRoute keeps your library in your Windows profile and the managed copies of your files in `Documents\PaperRoute Library`. When the two disagreed, as on a second computer that shares Documents, after a reinstall that started with an empty library before **Restore Backup...**, or after a library was recovered from its older safety copy, the first save deleted the packet snapshots of every manuscript the library did not contain. It now leaves the folders of manuscripts the library does not contain alone, as it already did for version files, and startup recovery puts back any file of such a manuscript that an interrupted save had set aside, packet or version, instead of deleting it. The managed packet files of a manuscript that is not in the saved library now stay on disk, as its version files already did; that includes a manuscript you delete.

## Before upgrading

v0.9.1 uses the same **Schema 9** library as v0.9.0 and migrates no data; v0.9.0 can still open a library v0.9.1 has used. If PaperRoute runs on more than one computer that shares a Documents folder, update every one of them before saving on any of them. The [upgrade notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/v0.9.1/UPGRADE_NOTES.md) have the details.

## Verification

Every automated test passes, with none skipped, including new tests that fail on v0.9.0. The published assets, the live updater from v0.9.0 with byte-identical data files, and the fix on the installed app are recorded in [#108](https://github.com/JUhalt/PaperRoute-Tracker/issues/108).

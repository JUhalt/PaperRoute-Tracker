# PaperRoute Tracker v1.0.1-rc.1 — Certification Follow-ups

**Local-first, privacy-focused app for tracking academic manuscripts from draft through submission, revision, and publication.**

This Preview candidate is PaperRoute 1.0.1, a patch for v1.0.0. It fixes two ways the manuscript page could lose author data, both present since v0.2.0, and it takes what 1.0's certification noted. It adds no window, and your library stays on Schema 9. v1.0.0 remains the current Stable release while this candidate is certified.

## Fixed

- **ORCID works imported from a manuscript page are kept.** On a manuscript page's Authors tab, **Manage Library** opens Authors & Affiliations. An ORCID works import started there, with **ORCID...**, did two things it should not have. It wrote the page's unsaved author changes to disk without **Save**, so **Discard** did not undo them on disk. And the next save of the library dropped the imported works, although "ORCID Import Complete" had said they were imported; they never appeared on the Board. This was present since v0.2.0. An import from **Library > Authors & Affiliations** was not affected, and neither was an import that applied only an iD, names or affiliations. An import started from the manuscript page now leaves the page's unsaved changes unsaved, and its imported works are kept. _PENDING
- **If you lost works this way,** import them again from **Library > Authors & Affiliations**. If you chose **Discard** after such an import, open that manuscript and check its Authors tab.
- **People a Crossref lookup added are kept until Save.** On a manuscript page, **DOI & Crossref Metadata...** can add new people and affiliations, which wait until you save the page. If **Submission Readiness...**, **Manage Library** or **Journal, Preprint & Links...** (closed with OK) was opened before **Save**, they were lost. The manuscript then listed them as "[Missing author record]", and no message appeared. This was present since v0.2.0, and through Submission Readiness since v0.4.0. People the lookup matched to someone already in your library were not affected, and neither was a lookup saved before any of those windows was opened. The people and affiliations a lookup added are now kept when those windows are opened before Save. _PENDING
- **If a manuscript shows "[Missing author record]" this way,** remove those entries on its Authors tab and run the Crossref lookup again. The names and iDs the lookup supplied were never saved, so no backup holds them.

## Changed

- **The Board's stage and sort filters.** Each step through the open stage list redrew the Board, which held the window on a large library. The Board now redraws for a stage or sort choice once, when the open list closes, with the shelves' drawing held while it does. A step with the arrow keys on the closed box still redraws at once. _PENDING
- **The first online request after a resume.** After a computer or a virtual machine resumes, the first online request could fail with "couldn't reach", as an update check did in 1.0's certification. A connection the network dropped while the computer slept can still be waiting in PaperRoute's pool. When a request that only reads and carries no content, such as an update check, gets no answer at all, PaperRoute now sends it once more, through the same Online services checks. A request with content, such as an AI assistant's text, is never sent twice. Whether one more try is enough after a real resume is checked on this candidate ([#339](https://github.com/JUhalt/PaperRoute-Tracker/issues/339)).
- **If your studies were on OSF.** A new User Guide section, [If your studies were on OSF](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/docs/USER_GUIDE.md#if-your-studies-were-on-osf), is for researchers who kept a study's plan, materials or data in an OSF project. It says what changes on OSF and when, with each fact linked to the Center for Open Science's own pages, what PaperRoute can hold for a study today, and the steps to take first.
- **Behind the scenes:** the repository holds WinGet manifest files for v1.0.0, under [packaging/winget](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/packaging/winget/README.md), checked by two tests; nothing has been submitted, and PaperRoute is not in WinGet's catalog. The official RO-Crate validator, roc-validator 0.12.1, found no REQUIRED failures in the RO-Crate metadata of PaperRoute's packet export; the [record](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/ManualCertification/v0.9-RO-Crate-Evaluation/README.md) has the commands and counts. Two keyboard tests that failed while someone was using the PC now release the mouse buttons and modifier keys before they press a key, and a new test checks that each list that scrolls sideways measures again when its rows change.

## Code signing

**PaperRoute 1.0.1 is not code-signed.** The project's application to the SignPath Foundation for free code signing was declined on October 31, 2026, for want of signs of public adoption, and a new application is welcome later ([#216](https://github.com/JUhalt/PaperRoute-Tracker/issues/216)). That issue, planned for v1.1, holds the routes to try next: WinGet, a Microsoft Store (MSIX) build, or a new application once the project has external references. Until releases are signed, your browser and Windows may warn before Setup runs; the User Guide's [Installing](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/docs/USER_GUIDE.md#installing) section explains the warning and how to check the download against `SHA256SUMS.txt`. The [code signing policy](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/CODE_SIGNING.md) says what will be signed, how, and who approves each signing request.

## Before trying this candidate

1.0.1 uses the same **Schema 9** library as v0.9.0 to v1.0.0 and migrates no data. It changes no library file's layout, so v1.0.0 can still open a library 1.0.1 has used. Updating from v1.0.0 or v0.9.2 asks about unsaved edits first. To be offered this Preview, choose **Preview** under **Settings → Preferences... → Update channel**, and choose **Stable** again once v1.0.1 is out: while the channel is Preview, the Stable release is not offered. An install made with this Preview's Setup starts on the Stable channel. If PaperRoute runs on more than one computer that shares a Documents folder, update every one of them before saving on any of them. The [v1.0.0 release notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/docs/releases/1.0.0.md) describe what you receive with 1.0.1 if you are updating from v0.9.2. The [upgrade notes](https://github.com/JUhalt/PaperRoute-Tracker/blob/v1.0.1-rc.1/UPGRADE_NOTES.md) have the details.

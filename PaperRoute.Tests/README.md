# PaperRoute.Tests

The automated test suite for PaperRoute Tracker: MSTest 4 tests written in VB.NET, on .NET 10 for Windows. Most tests call the services and models directly. The UI tests build the real windows, and the real main window (`LibraryBoard` drives `Form1`), on a temporary library. On master at e31b243 the suite has 156 source files, 1,311 test methods and 402 data rows, which run as 1,598 results. They are counted from the code: each `<TestMethod>` is one method, and each `<DataRow>` one result of its method, so a method with rows runs once per row. On CI, which sets `PAPERROUTE_FILE_DIALOG_TESTS` and leaves out the 2 `OnScreen` tests below, 1,596 run and pass (run 41129181362, at e31b243); on a computer with neither variable set, 1,591 pass, the 5 file-dialog rows below are skipped, and the 2 `OnScreen` tests are Inconclusive. At the audit (master at fb24242 plus its change) the suite had 147 source files, 1,188 test methods and 363 data rows, which ran as 1,451 results.

This file is #150's audit record, for #44 box 4 to cite: what the suite proves, the safety coverage it keeps, and what the v0.9.2 pass merged. The pass covered the 147 files on master at fb24242.

## Running it

From the repository root:

```powershell
dotnet test PaperRoute.Tests/PaperRoute.Tests.vbproj --configuration Release
```

CI runs the whole suite in Release, except the `OnScreen` tests below, for every pull request to master and every push to it (`.github/workflows/build.yml`), and fails unless every test it runs passes, none skipped or inconclusive, as the release workflow does (#196); its test run took 22 minutes 20 seconds at e31b243, and 11 minutes 47 seconds at fb24242. A local run takes longer: the audit's Debug runs took 24 to 69 minutes, with other work on the computer. To run one class, add `--filter "FullyQualifiedName~BackupRestoreTests"`. `ResponsivenessBudgetTests` is timed, and it holds each budget doubled in a Debug build and tripled again on GitHub Actions (`GITHUB_ACTIONS=true`). Many UI tests move the keyboard focus. On a busy computer, or with another test run on the same desktop, one of these can fail; run that class again alone, on a quiet computer, before reading the failure as a regression.

Five tests take an on-demand variable:

- `WindowChromeTests.TheFileDialogsGetTheThemesTitleBarFromTheDialogHook` (category `OnDemand`, five rows) is skipped unless `PAPERROUTE_FILE_DIALOG_TESTS` is set, because a file dialog leaves Explorer's view state for its folder under HKCU. CI sets it on its disposable runners (#196), and `ManualCertification/Build-ReleaseCandidate.ps1` leaves the category out. Do not set it on your own computer.
- `CertificationFixtureTests.WritesTheFixtureForACertificationOnDemand` runs every time, into its own temporary folder. With `PAPERROUTE_CERTIFICATION_FIXTURE` naming a new or empty folder, it writes the standing certification fixture and its backup there for the release VM, as [ManualCertification/README.md](../ManualCertification/README.md#standing-certification-fixture) describes.
- `PacketExportTests.SyntheticExport_WritesCrateForOfflineChecker` runs every time. With `PAPERROUTE_EXPORT_EVIDENCE_DIR` set, it also copies the synthetic export, `paperroute-export-synthetic.zip`, into that folder.
- `MotionFadeTests.AClickDuringTheFadeOnTheScreenReachesTheTabWindowsFinds` and `MotionFadeTests.ThePictureIsThePageLeft` (category `OnScreen`) put the test window on the screen for a moment, so they need `PAPERROUTE_ON_SCREEN_TESTS=1` on an unlocked desktop, and are Inconclusive without it. CI and `ManualCertification/Build-ReleaseCandidate.ps1` leave the category out; the release certification runs it by hand, with the variable set and `--filter "TestCategory=OnScreen"`.

A new test follows two rules:

- **Forms only on `StaRunner`.** A test that makes a Form, or any other control, makes it inside `StaRunner.Run` (or `RunOnStaThread` in `TestSupport`), never on the test's own thread or a thread it starts. A theme test passes its color mode to `StaRunner.Run` instead of setting it. The runner fails a stuck test in bounded time, closes the windows it left and puts the color mode back (#134). `StaRunnerGuard` fails any test that made a form on its own thread, because a color-mode test after it in the same process can hang (#185). The guard does not look at a thread the test starts, so nothing catches a form made there: make it on the runner.
- **Storage only under `RootOverride`.** A test that can reach a default storage root (settings, error reports, Diagnostics, the main window) sets `StorageEnvironment.RootOverride` to a folder from `CreateTemporaryRoot()` in its `TestInitialize`, and in its `TestCleanup` sets it back to `Nothing` and calls `DeleteTemporaryRoot`. The override is shared by the whole process, so the class is marked `<DoNotParallelize>`. Library files go under a temporary root too. No test may read or write the researcher's own profile; the view catalog checks this for every view (`StorageEnvironment.DefaultRootUses` stays 0).

## Safety coverage kept

The pass changed no test in these files. Each area names its files and the tests that carry its main claims; the files hold the rest of the proof.

- **Packet and version deletion.** A deleted version or packet file moves to `removed\<date>` when the library is saved, never before; a failed JSON write puts it back; a folder in use is left and named; another manuscript's files and shared files are never swept; a version a packet uses cannot be deleted; a linked file is never deleted. Files: `VersionDeletionTests`, `ManagedPacketDeletionTests`, `SubmissionPacketReferenceSafetyTests`, `SubmissionPacketServiceTests`, `RcSafetyTests`. Key tests: `RepositorySave_AfterManagedPacketFileRemovalMovesItToRemoved`, `RepositorySave_WhenJsonWriteFailsRestoresDeletedVersionSnapshot`, `RepositorySave_LeavesPacketFilesOfManuscriptNotInLibrary`.
- **Migration and schema markers.** Each step upgrades without rewriting `manuscripts.json` and keeps its `schema.vN.bak`; invalid data blocks an upgrade; a future, malformed, versionless, non-numeric or zero marker is refused and kept byte for byte; a locked marker keeps the earlier backup and the retry completes. Files: `MigrationTests`, `Schema3MigrationTests` to `Schema8MigrationTests`, `Schema4CertificationTests`, `JournalShortlistTests`, `CertificationFixtureTests`. Each old test built its input, made one call and made one assertion; its row builds the same input and makes the same call and the same assertion, so a row passes exactly when its old test did.
